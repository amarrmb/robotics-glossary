If [perception](/robotics-glossary/concepts/perception/slam/) is how a robot **senses the world**, the concepts in this section are how it **acts on the world**. They answer two questions that every robot has to solve, every control cycle, forever:

1. **Where am I really?** — sensors are noisy, biased, and incomplete, so the true state has to be *estimated*, not read off directly. This is **state estimation**.
2. **What do I do about it?** — given that estimate and a goal, what commands go to the motors? This is **control** (and the **planning** that decides the goal in the first place).

<Aside type="tip">
The one-sentence version: **you cannot control what you cannot estimate, and you cannot estimate without a model.** That sentence is the whole section. Estimation needs a model of how the system moves; control acts on the estimate; both lean on the same physics ([dynamics](/robotics-glossary/concepts/fundamentals/dynamics/)) and the same math ([state-space](/robotics-glossary/concepts/control/state-space/)).
</Aside>

## The loop that ties it together

Every autonomous robot runs some version of this loop, hundreds of times a second:

```
        ┌──────────────────────────────────────────────────────────┐
        │                                                            │
        ▼                                                            │
   ┌─────────┐    noisy      ┌────────────┐   clean    ┌─────────┐   │
   │ SENSORS │ ─ readings ─► │  ESTIMATE  │ ─ state ─► │ DECIDE  │   │
   │ (camera,│               │ filters +  │           │ plan +  │   │
   │ IMU,    │               │ state est. │           │ control │   │
   │ encoders)│              └────────────┘           └────┬────┘   │
   └─────────┘                                             │        │
        ▲                                            commands       │
        │                                                 ▼         │
        │              ┌──────────┐   torques/      ┌──────────┐    │
        └── the world ─┤ ACTUATORS │◄─ positions ───┤  (model) │────┘
            changes    └──────────┘                 └──────────┘
```

- **Estimate** turns raw, noisy sensor data into a trustworthy state. The tools here are the [filters](/robotics-glossary/concepts/control/kalman-filter/).
- **Decide** picks a goal ([planning](/robotics-glossary/concepts/control/motion-planning/)) and computes the commands to reach it ([control](/robotics-glossary/concepts/control/pid/)).
- The **model** — the system's [dynamics](/robotics-glossary/concepts/fundamentals/dynamics/) in [state-space](/robotics-glossary/concepts/control/state-space/) form — is what *both* halves depend on. That is why a glossary section can hold estimation, planning, and control together: they share a model.

## Where to start

The entries build on each other. If you're new to the area, read them in this order — each one assumes the ones before it:

1. **Foundations** — [Robot Dynamics](/robotics-glossary/concepts/fundamentals/dynamics/) and the [Jacobian](/robotics-glossary/concepts/fundamentals/jacobian/) (the physics: what forces move a robot, and how joint motion maps to the world).
2. **The shared language** — [State-Space Representation](/robotics-glossary/concepts/control/state-space/) (how estimation and control both describe a system).
3. **Estimation** — [State Estimation](/robotics-glossary/concepts/control/state-estimation/) → [Kalman Filter](/robotics-glossary/concepts/control/kalman-filter/) → [Complementary Filter](/robotics-glossary/concepts/control/complementary-filter/), plus [System Identification](/robotics-glossary/concepts/control/system-identification/) (building the model from data).
4. **Control** — start with [PID](/robotics-glossary/concepts/control/pid/) (the workhorse), then step up to [LQR](/robotics-glossary/concepts/control/lqr/) and [MPC](/robotics-glossary/concepts/control/mpc/) (optimal and constraint-aware), and [Force / Impedance Control](/robotics-glossary/concepts/control/force-control/) for contact.

<Aside type="note">
**Why this matters in practice.** Modern robot-learning policies (the [VLA models](/robotics-glossary/concepts/ai/vla-models/) and [imitation learning](/robotics-glossary/concepts/learning/imitation-learning/) elsewhere in this glossary) still output *actions* that run on top of this stack — a learned policy decides *what* to do, but estimation and low-level control are what make the robot do it safely and accurately. The neural net is the top of the pyramid; this section is the base.
</Aside>
